# 钱包卡片识别验证记录

[English](wallet-card-detection.md) · 简体中文

> 这是上游针对特定设备和版本的验证记录，不代表汉化版已在所有 iPhone 上完成实机测试。

## 复现过程与原因

iPhone 15 Pro（iOS 18.6.2）可以正常连接，但用户双击侧边按钮、通过面容 ID 验证并点选卡片后，程序仍未识别出卡片。在同一次操作中对比两种日志服务发现，`com.apple.syslog_relay` 没有返回卡片路径，而 `com.apple.os_trace_relay` 会在跨多行的资源查询记录中包含这些路径。

原生辅助程序现在通过 MobileDevice 服务连接请求统一活动日志流，并解析分帧记录。应用仍可独立运行，无需另装设备日志工具。原有卡片过滤规则继续从 `.pkpass` 路径识别卡片。若日志读取意外退出，应用也会显示辅助程序的诊断信息，并重置识别状态。

## 已验证的环境

| 项目 | 版本 |
| --- | --- |
| iPhone | iPhone 15 Pro（`iPhone16,1`），iOS 18.6.2 |
| Mac | MacBook Air（M3，2024），macOS 26.6.2 |
| 源码基线 | AirCard 1.2.3，提交 `02b5ba8` |

最初的问题报告附有 macOS 26.2 截图，但此次验证使用的 Mac 报告为 macOS 26.6.2；不能把 macOS 26.2 记为已验证版本。

修改后，实时识别共找到 8 个卡片标识，测试者确认卡片已出现在应用中。本次只测试识别，**没有向卡片写入图片**。停止辅助程序后，界面正确退出识别状态；再次开始识别仍可连接，也没有丢失已识别的卡片。

[问题 #28](https://github.com/Mak5er/AirCard/issues/28) 提到的 iPhone 17 / iOS 27 组合不在本次验证范围内。其他设备和系统版本也仍需验证。

## 自动检查

```sh
python3 -m unittest discover -s tests -v
bash build.sh
```

识别测试覆盖日志帧拆分与合并、plist 回复和活动记录的不同字节序、断线、错误长度、截断记录，以及跨多行的卡片路径能否进入原有识别规则。测试数据只包含合成的卡片标识。原生日志读取测试需要 macOS 和 Xcode 命令行工具。

## 协助验证其他设备

如果设备已连接但卡片仍未出现，请尝试此版本，并反馈 iPhone 型号、iOS 版本、macOS 版本、所用的 AirCard 提交编号，以及在“钱包”中点选卡片后是否出现识别结果。可以附上程序显示的扫描错误提示；**请勿公开原始设备日志或完整卡片标识**。
